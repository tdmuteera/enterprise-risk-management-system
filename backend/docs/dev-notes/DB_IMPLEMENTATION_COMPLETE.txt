                         SCHEMA SUMMARY (7 Tables)
================================================================================

TABLE: departments (4 records)
  Columns: id (UUID PK), name, code (4-char unique), description, head_of_dept,
           is_active, created_at, updated_at
  Indexes: name (unique), code (unique), is_active
  Sample:  Finance (FIN), HR, Academic Affairs (ACAD), IT

TABLE: users (7 records)
  Columns: id (UUID PK), email (unique), hashed_password, full_name, role (ENUM),
           department_id (FK), is_active, last_login, created_at, updated_at
  Indexes: email (unique), role, department_id, is_active
  Roles:   admin, risk_officer, dept_user, executive
  Sample:  7 users with different roles and departments

TABLE: risks (10 records)
  Columns: id (UUID PK), title, description, category (ENUM), department_id (FK),
           owner_id (FK), likelihood (1-5), impact (1-5), velocity (1-5),
           detectability (1-5), risk_score (FLOAT), status (ENUM),
           institutional_risk_index, created_at, updated_at
  Constraints: CHECK constraints on all 1-5 fields
  Indexes:    title, category, department_id, owner_id, status,
              COMPOSITE (department_id, status), risk_score DESC
  Formula:    risk_score = likelihood × impact × velocity × detectability
  Range:      1.0 to 625.0
  Sample:     10 risks across Finance, HR, Academic, IT departments

TABLE: risk_links (3 records)
  Columns: id (UUID PK), source_risk_id (FK), target_risk_id (FK),
           link_type (ENUM), weight (0.0-1.0), notes, created_by_id (FK),
           created_at
  Types:   causes, related_to, escalates, triggers
  Sample:  Expenditure→Governance, DataBreach→Cybersecurity,
           DataBreach→Reputation

TABLE: risk_history (APPEND-ONLY AUDIT LOG)
  Columns: id (UUID PK), risk_id (FK), action (ENUM), changed_by_id (FK),
           changed_at, previous_values (JSONB), new_values (JSONB),
           ip_address, user_agent
  Actions:  created, updated, status_changed, score_changed, deleted
  Indexes:  changed_at, changed_at DESC
  Feature:  IMMUTABLE - NEVER updated or deleted

TABLE: mitigation_actions (3 records)
  Columns: id (UUID PK), risk_id (FK), description, assigned_to_id (FK),
           due_date, completion_date (nullable), status (ENUM),
           effectiveness_score (1-5, nullable), created_at, updated_at
  Status:   Pending, In-Progress, Overdue, Completed
  Sample:   Budget approval, Encryption upgrade, EDR threat detection

TABLE: alerts (4 records)
  Columns: id (UUID PK), alert_type (ENUM), risk_id (FK, nullable),
           message, severity (ENUM), is_read, is_dismissed,
           created_for_role (ENUM), created_at
  Types:   HighRisk, ForensicFlag, OverdueMitigation, EmergingInstitutional,
           RiskSuppression, RiskChainDetected
  Severity: Info, Warning, Critical
  Target:   all, executive, risk_officer
  Sample:   4 alerts ranging from Critical to Warning

                       KEY FEATURES IMPLEMENTED
================================================================================

✅ UUID Primary Keys
   - PostgreSQL native UUID type
   - auto.uuid4 default
   - Globally unique identifiers

✅ Multi-Factor Risk Scoring
   - likelihood (1-5): Probability
   - impact (1-5): Severity
   - velocity (1-5): Speed of materialization
   - detectability (1-5): Detection difficulty (inverse)
   - risk_score = L × I × V × D (range: 1.0-625.0)
   - Database-level CHECK constraints

✅ Composite Indexes for Performance
   - (department_id, status) - For filtering risks
   - risk_score DESC - For risk ranking
   - changed_at DESC - For audit trail queries

✅ Immutable Audit Log
   - RiskHistory table: append-only
   - JSONB storage for before/after values
   - IP address and user agent tracking
   - Never updated or deleted

✅ Cross-Department Linkage
   - RiskLink table: identifies interdependencies
   - Weight (0.0-1.0): strength of relationship
   - Link types: causes, relates, escalates, triggers

✅ Timestamps
   - created_at: auto-set on insert
   - updated_at: auto-set on insert and update
   - changed_at: For audit trail entries

✅ Relationship Graph
   - Department → Users (1:N)
   - Department → Risks (1:N)
   - User → Owned Risks (1:N)
   - Risk → RiskHistory (1:N, cascade delete)
   - Risk → RiskLinks (1:N, bidirectional)
   - Risk → Mitigations (1:N)
   - Risk → Alerts (1:N)

================================================================================
                         SETUP & USAGE
================================================================================

Quick Start (5 minutes):

1. Update .env:
   DB_URL=postgresql+asyncpg://erm_user:password@localhost:5432/erm_db

2. Create database:
   createdb -U postgres erm_db
   psql -U postgres -d erm_db -c \
     "CREATE USER erm_user WITH PASSWORD 'password'; \
      GRANT ALL PRIVILEGES ON DATABASE erm_db TO erm_user;"

3. Seed database:
   python db_seed.py
   
   This will:
   - Create all tables with constraints
   - Add indexes
   - Populate 24 sample records
   - Create audit log entries

4. Verify:
   psql -U erm_user -d erm_db -c "SELECT COUNT(*) FROM risks;"
   # Output: 10

5. Start server:
   uvicorn main:app --reload

Setup Methods:

Option A: Docker (Easiest)
  docker-compose up -d
  docker-compose exec api python db_seed.py

Option B: Local PostgreSQL (Manual)
  postgres setup → python db_seed.py

Option C: Alembic (Best Practice)
  alembic upgrade head
  python db_seed.py
