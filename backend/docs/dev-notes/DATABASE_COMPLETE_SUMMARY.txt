🗄️ SCHEMA OVERVIEW (7 TABLES)
════════════════════════════════════════════════════════════════════════════

1️⃣ DEPARTMENTS (4 records)
   Fields: id (UUID PK), name, code (4-char unique), description,
           head_of_dept, is_active, created_at, updated_at
   
   Records:
   • Finance (FIN)
   • HR (HR)
   • Academic Affairs (ACAD)
   • IT (IT)

2️⃣ USERS (7 records)
   Fields: id (UUID PK), email (unique), hashed_password, full_name,
           role (ENUM), department_id (FK), is_active, last_login,
           created_at, updated_at
   
   Roles: admin, risk_officer, dept_user, executive
   
   Records:
   • 1 admin
   • 2 risk officers
   • 3 department users
   • 1 executive

3️⃣ RISKS (10 records)
   Fields: id (UUID PK), title, description, category (ENUM),
           department_id (FK), owner_id (FK),
           likelihood (1-5), impact (1-5), velocity (1-5),
           detectability (1-5), risk_score (FLOAT),
           status (ENUM), institutional_risk_index,
           created_at, updated_at
   
   Constraints: CHECK on likelihood, impact, velocity, detectability
   Indexes: (department_id, status), risk_score DESC
   
   Formula: risk_score = likelihood × impact × velocity × detectability
   Range: 1.0 to 625.0
   
   Sample Risks:
   • Budget Overrun (score: 48.0)
   • Irregular Expenditure (score: 150.0)
   • Staff Attrition (score: 96.0)
   • Payroll System Failure (score: 25.0)
   • Student Data Breach (score: 144.0)
   • Cyber Security Threat (score: 320.0)
   • System Downtime (score: 40.0)
   • And 3 more...

4️⃣ RISK LINKS (3 records)
   Fields: id (UUID PK), source_risk_id (FK), target_risk_id (FK),
           link_type (ENUM), weight (0.0-1.0), notes,
           created_by_id (FK), created_at
   
   Link Types: causes, related_to, escalates, triggers
   
   Sample Links:
   • Expenditure → Governance (causes, weight: 0.9)
   • Data Breach → Cybersecurity (related_to, weight: 0.8)
   • Data Breach → Reputation (escalates, weight: 0.95)

5️⃣ RISK HISTORY (Immutable Audit Log)
   Fields: id (UUID PK), risk_id (FK), action (ENUM),
           changed_by_id (FK), changed_at, previous_values (JSONB),
           new_values (JSONB), ip_address, user_agent
   
   Actions: created, updated, status_changed, score_changed, deleted
   
   Feature: APPEND-ONLY - Never updated or deleted
   
   Use Case: Complete forensic audit trail of all risk changes

6️⃣ MITIGATION ACTIONS (3 records)
   Fields: id (UUID PK), risk_id (FK), description,
           assigned_to_id (FK), due_date, completion_date,
           status (ENUM), effectiveness_score,
           created_at, updated_at
   
   Status: Pending, In-Progress, Overdue, Completed
   
   Sample Mitigations:
   • Budget Overrun: "Implement strict budget approval process"
   • Student Data Breach: "Upgrade encryption protocols"
   • Cyber Threat: "Implement EDR threat detection"

7️⃣ ALERTS (4 records)
   Fields: id (UUID PK), alert_type (ENUM), risk_id (FK, nullable),
           message, severity (ENUM), is_read, is_dismissed,
           created_for_role (ENUM), created_at
   
   Types: HighRisk, ForensicFlag, OverdueMitigation,
          EmergingInstitutional, RiskSuppression, RiskChainDetected
   
   Severity: Info, Warning, Critical
   Target: all, executive, risk_officer
   
   Sample Alerts:
   • HIGH_RISK: "Critical: Student data breach detected"
   • OVERDUE_MITIGATION: "Budget risk mitigation approaching deadline"
   • RISK_CHAIN_DETECTED: "Expenditure → Governance chain detected"

🔐 ADVANCED FEATURES
════════════════════════════════════════════════════════════════════════════

✅ Multi-Factor Risk Scoring
   Formula: likelihood × impact × velocity × detectability
   • Likelihood (1-5): How likely is the risk?
   • Impact (1-5): How severe if it occurs?
   • Velocity (1-5): How fast does it materialize?
   • Detectability (1-5): How hard is it to detect?
   
   Result: Scores ranging from 1.0 to 625.0
   Database: CHECK constraints enforce 1-5 range

✅ Immutable Audit Trail
   Table: risk_history
   • Records every change to a risk
   • Stores previous_values and new_values as JSONB
   • Append-only: never updated or deleted
   • Includes IP address and user agent
   • Full forensic investigation support

✅ Cross-Department Risk Linkage
   Table: risk_links
   • Identifies interdependencies between risks
   • Weight (0.0-1.0) indicates strength
   • Link types: causes, relates, escalates, triggers
   • Enables risk chain detection

✅ Composite Indexes for Performance
   • (department_id, status) - Filter risks by dept & status
   • risk_score DESC - Rank risks by score
   • changed_at DESC - Query audit trail chronologically

✅ Type Safety
   • PostgreSQL native UUID type
   • Type-safe ENUMs for all categories
   • Database-level CHECK constraints
   • Foreign key referential integrity

⚡ QUICK START
════════════════════════════════════════════════════════════════════════════

Step 1: Update .env
   DB_URL=postgresql+asyncpg://erm_user:password@localhost:5432/erm_db

Step 2: Create PostgreSQL database
   createdb -U postgres erm_db
   psql -U postgres -d erm_db -c "
     CREATE USER erm_user WITH PASSWORD 'password';
     GRANT ALL PRIVILEGES ON DATABASE erm_db TO erm_user;"

Step 3: Seed database
   python db_seed.py
   
   This will:
   ✓ Create all 7 tables
   ✓ Create 8 ENUM types
   ✓ Add CHECK constraints
   ✓ Create 15+ indexes
   ✓ Seed 24 sample records

Step 4: Verify
   psql -U erm_user -d erm_db -c "SELECT COUNT(*) FROM risks;"
   # Output: 10

Step 5: Start server
   uvicorn main:app --reload
